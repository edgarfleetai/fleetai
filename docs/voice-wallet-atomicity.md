# Безопасное голосовое пополнение кошелька

## Обнаруженный блокер

`fleetai/routes.py::_sync_daily_rent(session, car)` вызывает `session.commit()` как при создании стартового маркера, так и после начислений. В существующем маршруте `/api/driver-wallet/topup` затем создаются кошелёк, `Operation` и `Income` и выполняется отдельный `commit()`.

Это означает, что прямой вызов `_sync_daily_rent` внутри нового голосового подтверждения **не даёт атомарности**. При сбое после начисления аренды, но до зачисления платежа, состояние будет частично обновлено.

## План безопасной реализации

1. Выделить из `_sync_daily_rent` низкоуровневый вариант, который только добавляет записи в переданную сессию, **не коммитит**. Сохранить существующее поведение старого маршрута через обёртку с коммитом.
2. В подтверждении голосового платежа начать одну транзакцию, заблокировать `Car`, сверить код и имя водителя с подписанным предпросмотром.
3. Проверить уникальность `request_key` на уровне БД и обеспечить безопасную обработку конкурентных повторов.
4. В той же транзакции начислить аренду, добавить `DriverWalletTransaction`, `Operation`, `Income` и квитанцию; затем выполнить один `commit()`.
5. При любом исключении откатить **все** изменения. Добавить тесты с искусственным исключением между начислением аренды и зачислением платежа.
6. Отдельно обработать погашение `DriverDebt`/`DriverDebtPayment`: это не эквивалентно пополнению кошелька.

## Текущий статус

Новый голосовой wallet API пока не выполняет запись. Подключение iPhone и продакшен не включены.
