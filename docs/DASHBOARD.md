# FleetAI 4.0 — новый дашборд (отдельный сайт)

Код: `dashboard/` (Flask, один файл страницы `dashboard/static/index.html` в дизайне прототипа).
Старый FleetAI (`fleetai/`, сервис `fleetai-1`) не меняется и продолжает работать для ввода операций,
Telegram, cron и договоров.

## Что подключено

| Раздел | Источник | Статус |
|---|---|---|
| Главная | `cars` | ✅ статус парка, сданы в аренду, собственники, требуют внимания, мониторинг |
| Автомобили | `cars` | ✅ карточки, фильтры, таблица; баланс аренды — «не подключён» |
| Водители | `cars.driver` | ✅ кто на какой машине |
| Мониторинг | Wialon (token/login + core/search_items) | ✅ живые позиции, обновление каждые 30 с |
| Финансы, Инвесторы, Ремонты | — | «Раздел подключается»: цифры появятся после сверки со старым FleetAI |
| Аренда, Договоры, Задачи, Настройки | — | в разработке |

Тестовых данных на странице нет: всё, что не подключено, так и подписано.

## Безопасность
- **Только чтение.** Сессия PostgreSQL открывается с `default_transaction_read_only=on`; в production
  используется отдельная роль только с `SELECT` (ниже). В коде дашборда нет ни одного INSERT/UPDATE/DELETE (проверяется тестом).
- **Wialon:** клиент разрешает только `token/login` и `core/search_items`; любые команды машинам отклоняются в коде.
- **Вход:** тот же логин и пароль владельца, что в FleetAI (`auth_owners`), проверка хеша без записи в базу.
  Подписанная cookie `__Host-fa4` (Secure, HttpOnly, SameSite=Lax), 8 часов. Смена пароля в FleetAI завершает сессии дашборда.
  Не больше 5 неудачных попыток за 15 минут. Вход и выход защищены проверкой origin + CSRF.
- Заголовки: CSP (`connect-src 'self'`, `frame-ancestors 'none'`), HSTS, `X-Frame-Options: DENY`, `no-store`.

## Развёртывание (делает владелец)

**Выбрано владельцем 14.11.2026 — простой путь:** `DASHBOARD_DATABASE_URL` = тот же `DATABASE_URL`, что у `fleetai-1`.
Защита от записи в этом случае одна — сессия `default_transaction_read_only=on` и отсутствие записывающего SQL
в коде (тест). Отдельную роль (раздел 1) можно добавить позже, заменив только эту переменную.

### 1. (Необязательно) Роль только для чтения в Neon
Neon Console → проект → **SQL Editor** → ветка production (`import-2026-08-05T15:17:33.988Z`).
Пароль придумать заранее (или сгенерировать командой из `docs/RELEASE_LOGIN_AND_MONITOR.md`):
```sql
CREATE ROLE dashboard_ro WITH LOGIN PASSWORD '<пароль>';
GRANT CONNECT ON DATABASE neondb TO dashboard_ro;
GRANT USAGE ON SCHEMA public TO dashboard_ro;
GRANT SELECT ON ALL TABLES IN SCHEMA public TO dashboard_ro;
ALTER DEFAULT PRIVILEGES IN SCHEMA public GRANT SELECT ON TABLES TO dashboard_ro;
```
Роль создаётся именно через SQL, а не через раздел Roles: роли из консоли Neon получают права `neon_superuser`.
Проверка: `SELECT has_table_privilege('dashboard_ro', 'cars', 'INSERT');` → `false`.

Строка подключения: как у основной, но с пользователем `dashboard_ro` и его паролем.

### 2. Новый сервис в Render
**New → Web Service** → репозиторий `edgarfleetai/fleetai`, ветка `feature/dashboard-v4`
(после слияния PR — переключить на `main`; так production-сервис `fleetai-1` не передеплоивается ради дашборда).
- Build Command: `pip install -r requirements.txt`
- Start Command: `gunicorn dashboard.app:app --workers 1 --bind 0.0.0.0:$PORT`
- Health Check Path: `/healthz`
- Environment:
  - `DASHBOARD_DATABASE_URL` — значение `DATABASE_URL` из `fleetai-1` (или строка роли `dashboard_ro`)
  - `DASHBOARD_SECRET_KEY` — случайная строка 32+ символов
  - `DASHBOARD_PUBLIC_URL` — адрес сервиса, например `https://fleetai-dashboard.onrender.com`
  - `WIALON_TOKEN` — тот же, что у FleetAI

`--workers 1`: счётчик неудачных входов хранится в памяти процесса.

## Внесение операций (с 15.11.2026)
Кнопка «Операция» в шапке: машина, тип (доход / расход / ремонт / выплата инвестору), сумма, комментарий —
или сразу команда, как в старом FleetAI («703 получил 13000 / 665 замена стойки стаба цена 1000»).
1. «Проверить» — команда разбирается тем же `fleetai.parser.parse_message`; дашборд показывает тип, машину,
   категорию, сумму, запчасти. В базу ничего не пишется.
2. «Сохранить» — запись делает та же `fleetai.routes.save_operation`, что и `/api/add` старого FleetAI,
   поэтому операции, доходы, расходы, запчасти и склад записываются одинаково.

Защита: вход владельца, CSRF-токен + проверка origin, отпечаток команды (если её изменили после проверки — 409),
ключ идемпотентности (повторное нажатие не создаёт вторую запись), запрет кодов 119 и несуществующих машин.
Чтение по-прежнему идёт через сессию только для чтения; запись — отдельной сессией старого FleetAI.
Отключить запись полностью: `DASHBOARD_READ_ONLY=1` в Render.

## ИИ-помощник, задачи и история изменений (с 16.11.2026)

- **Помощник** (кнопка «Помощник» вверху): отвечает на вопросы о парке на Claude (`claude-opus-5-5`, effort medium,
  запасная модель при отказе — server-side fallbacks). Читает только через функции дашборда: машины, финансы, аренду,
  журнал, пробег и масло, ремонты, историю, GPS. Паспорта, телефоны и договоры ему не передаются, SQL у него нет.
  Сам умеет только ставить задачи. Деньги он лишь предлагает записать — запись проходит через командную строку
  после нажатия владельца. Вопрос выполняется в фоне (страница опрашивает `/api/v4/assistant/job/<id>`).
- Включение: в Render (fleetai-dashboard → Environment) переменная `ANTHROPIC_API_KEY`. Без неё помощник выключен.
  Необязательно: `ASSISTANT_DAILY_LIMIT` (вопросов в день, по умолчанию 150), `ASSISTANT_MODEL`, `ASSISTANT_EFFORT`.
  Лимит расходов ставится в console.anthropic.com.
- **Задачи**: таблица `dashboard_tasks` (новая, старый FleetAI её не читает). Раздел «Задачи» → «Мои задачи».
- **История изменений**: таблица `dashboard_audit_log` — каждая запись/правка/удаление через дашборд;
  раз в час снимок машин и операций за 120 дней (`dashboard_snapshot`, хранится 48 последних) сравнивается
  с прошлым, и изменения из бота/старого сайта пишутся как «бот / старый сайт». Видно в «Задачи» и во вкладке «История» машины.
- Откат: вернуть предыдущий коммит ветки; новые таблицы можно оставить — их никто, кроме дашборда, не читает.

## Договоры аренды в дашборде (с 16.11.2026)

- Раздел «Договоры» → «Новый договор» (или кнопка в карточке машины). Машина, аренда, залог,
  реквизиты авто и собственника подставляются сами.
- Гражданство: РФ, Узбекистан, Таджикистан, Кыргызстан, Туркменистан, другое. Для иностранцев —
  паспорт иностранного гражданина, миграционная карта, миграционный учёт, право на работу
  (патент / разрешение / ЕАЭС), страна выдачи прав, ИНН.
- «Сохранить черновик» — можно с пустыми полями; «Готово» — только когда всё заполнено (статус `ready`).
  PDF открывается кнопкой «PDF»; «Подписан на бумаге» сохраняет PDF в базе и блокирует изменения.
- Строки пишутся в существующую таблицу `driver_contracts`; поля иностранцев — в новую таблицу
  `dashboard_contract_extra` (только добавление). Паспортные данные отдаёт только
  `GET /api/v4/contracts/<id>` владельцу; в список, историю и помощнику они не попадают.
- Карточка машины: «Кабинет водителя ↗» открывает `/d?code=…` на этом сайте (просмотр владельцем, без оплаты);
  раньше вёл в старый FleetAI.
- «Ссылка водителю» в договоре: водитель по ссылке старого FleetAI (`/driver-contract?token=…`)
  проверяет и дозаполняет данные под своё гражданство и подписывает звонком (SMS.ru).
- «Ссылка водителю в кабинет» в карточке машины: разовая ссылка `/d#token=…` (этот сайт) на 24 часа для
  водителя без Telegram; вход живёт `DRIVER_LINK_SESSION_DAYS` (30) дней, закрывается при смене водителя
  или кнопкой «Закрыть доступ». В базе хранится только хэш ссылки.
- Порядок выкатки: сначала старый FleetAI (PR feature/driver-links → main), потом дашборд. Иначе
  ссылки откроет старый код: вход по ссылке он не пустит, договор иностранца примет как российский.
- Откат: вернуть ветку `feature/dashboard-v4` на предыдущий коммит; таблица `dashboard_contract_extra`
  никому не мешает.

## Оплаты, не попавшие в баланс водителя (с 16.11.2026)

До 15.11 команда «… получил …» записывала оплату водителя только как доход парка, без пополнения
кошелька — водитель выглядел должником. Во вкладке «Аренда» блок «Оплаты не попали в баланс водителя»
показывает такие оплаты с момента, когда текущий водитель взял машину (последний `driver_change_balance`),
кроме залогов, пополнений и банковских оплат. «Зачесть» пишет только `driver_wallet_transactions`
(`dispatcher_topup`, `external_id = op:<id>`) — операций и доходов не добавляет, повторно не зачтёт.
Похожие на дубль (та же сумма в те же 15 минут) не отмечены. Удаление или исправление зачтённой операции
через дашборд снимает зачёт. В таблице аренд показано «начислено по …», если суточная аренда начислена
не до сегодняшнего дня (машина не включена в авто-начисление старого FleetAI).

## Суточная аренда списывается дашбордом (с 17.11.2026)

Ночная задача старого FleetAI (`/api/cron/daily-rent-and-alerts`) перестала списывать аренду около 05.11.
По решению владельца дашборд каждые 30 минут вызывает ту же функцию `_sync_daily_rent` для всех машин
с водителем (кроме выбывших): одна запись за день (`DAILY_RENT:<дата>`), простой — 0, пропущенные дни
досписываются, повтор безопасен; каждая машина — под блокировкой строки `cars`. Уведомления в Telegram не
шлются. Кнопка «Досписать аренду сейчас» во вкладке «Аренда». Записи — в истории изменений.
Выключить: `RENT_ACCRUAL=False` в конфиге приложения (или откат коммита).

## Отчёт инвестору за период (с 18.11.2026)

«Инвесторы» → «Отчёт за период»: инвестор, любой из 12 последних периодов (16-е → 15-е), «Отчёт инвестору PDF»,
«Отчёт инвестору Excel» (CSV). Только чтение (`dashboard/invreport.py`, `GET /api/v4/investors/report`).
- Доля как в старом FleetAI: (доход − общие расходы) × процент из базы; минус расходы инвестора, GPS 500 ₽
  за машину и доля гаража 3 000 ₽ (если не внесены расходом).
- История: начислено / выплачено по периодам и сальдо с первого периода с данными (до 24 периодов).
- Проверки: переплата по сальдо, двойные выплаты (та же сумма за 3 дня), выплаты на чужую машину или
  на чужое имя, процент в базе ≠ договорённости, машина записана как своя, двойной доход за сутки,
  залог в доходе, другой номер машины в тексте, доход выше возможной аренды, записи на 119,
  двойные расходы, расходы только инвестора, крупные общие расходы. Ничего не исправляется автоматически:
  у каждой записи и у каждого пункта проверки есть ✎ (исправить) и ✕ (удалить) — та же правка, что в журнале
  (`POST /api/v4/op/<id>/edit|delete`, запись в истории изменений). `GET /api/v4/op/<id>` отдаёт операцию любой давности.
- Откат: вернуть предыдущий коммит ветки; новых таблиц нет.

### Отчёт для инвестора и объяснения (с 18.11.2026, по просьбе владельца)
- На сайте отчёт подробный (итоги, проверки, история, выплаты, доходы, расходы) — для владельца.
- Кнопки «Отчёт инвестору PDF / Excel» сначала открывают окно, где владелец сам пишет по каждой машине,
  почему столько заработано (пустое поле — предупреждение, второе нажатие сохраняет как есть). Текст хранится в
  новой таблице `dashboard_investor_notes` (`GET/POST /api/v4/investors/notes`, запись в истории изменений).
- В файл инвестору идёт только короткий отчёт: по машинам получено, расход (все расходы), прибыль, доля
  (по проценту минус расходы за его счёт) и объяснение под машиной; итог «к выплате» = доля − GPS и гараж −
  выплачено в периоде; список расходов. Проверки, история и доходы в файл не попадают.
- Расходы в файле («На что потрачены деньги») сгруппированы по машинам: описание из операции (что сделано),
  запчасти с маркой, местом, ценой и работой (таблица `parts` по `operation_id`), за чей счёт, итог по машине.
- PDF не печатается, а скачивается готовым файлом: его собирает сервер (`dashboard/invpdf.py`, reportlab,
  `GET /api/v4/investors/report.pdf?investor=&period=`, только чтение). Шрифт с русскими буквами — DejaVuSans
  на сервере (как у договоров); если его нет, окно покажет ошибку, а не файл с квадратиками.

### Кабинет водителя на новом сайте (с 18.11.2026, старый сайт выводится из работы)
- `dashboard/cabinet.py`, страница `static/driver.html`, адрес `/d`. База та же; правила доступа те же, что
  в старом FleetAI (`fleetai.auth`): разовая ссылка на 24 часа, сессия в `auth_sessions` (до 30 дней, cookie
  `__Host-fa4d`), проверка текущего водителя, эпохи и отзыва под блокировкой строки машины на каждом запросе.
  Водитель видит только свою машину; ссылка-токен передаётся только во фрагменте `#`, в запросе — 400.
- `GET /api/d/me`: баланс (сумма кошелька), аренда в день, на сколько дней хватит, отдельные долги,
  60 последних записей кошелька, подписанный договор (`/api/d/contract.pdf`). Ничего не пишет: аренду
  начисляет фоновая задача дашборда (`accrual.py`), а не открытие кабинета.
- `POST /api/d/pay` (CSRF + origin): платёж Т-Банка (Init) с возвратом в `/d`, строка `driver_bank_payments`
  со статусом pending. Зачисляет его по-прежнему вебхук банка (пока на старом сайте, шаг 2 переезда).
  Кнопка оплаты включается, когда в Render у дашборда заданы `TBANK_EACQ_TERMINAL_KEY` и
  `TBANK_EACQ_PASSWORD` (вносит владелец); до этого водитель видит «оплата скоро появится».
- Владелец: `/d?code=621` — просмотр кабинета любой машины (только чтение, без оплаты).
- Старые ссылки `/auth/driver#token=…` на старом сайте продолжают работать, пока он включён.
- Откат: вернуть ветку на предыдущий коммит; новых таблиц нет.

## Кабинет инвестора (с 19.11.2026)

Инвестор только смотрит результаты своих машин; ничего изменить не может.

- Владелец: «Инвесторы» → «Отчёт за период» → **«Кабинет инвестора»** → «Создать ссылку».
  Ссылка вида `/i#token=…` открывается один раз и действует 7 дней; после входа кабинет
  открыт на устройстве инвестора 180 дней. «Закрыть доступ» закрывает все входы и
  неиспользованные ссылки этого инвестора. «Посмотреть его глазами» — `/i?investor=ilya`
  (только для владельца).
- Что видит инвестор за выбранный период (текущий и 11 прошлых): к выплате
  (доля − GPS и гараж − выплачено), получено / расходы / прибыль / доля по каждой машине,
  объяснения владельца, на что потрачены деньги (работы, запчасти, цены), выплаты ему,
  и может скачать тот же PDF. Не видит: проверки, записи доходов, историю сальдо,
  других инвесторов, водителей и остальные машины.
- Хранение: новая таблица `dashboard_investor_access` (только хэши ссылок и входов),
  создаётся сама при первой ссылке. Остальные таблицы кабинет только читает.
- Откат: вернуть ветку на предыдущий коммит; таблицу можно оставить, её никто больше не читает.
