# FleetAI — настройка входа владельца на Render

**Не применять к production до завершения аудита административных маршрутов и проверки пользовательского интерфейса.** Черновой PR не сливать в main.

## Переменные Render (Environment)

- `FLASK_SECRET_KEY` — случайная секретная строка длиной не менее 32 байт. Используется для подписи cookie сессии. Хранить только в Render.
- `FLEETAI_ADMIN_PASSWORD_HASH` — результат `werkzeug.security.generate_password_hash(...)`, **не пароль в открытом виде**. Хранить только в Render.
- `FLASK_ENV` — не устанавливать в `development` на production, чтобы cookie оставалась Secure.

Генерация на своём компьютере, без отправки пароля в чат или GitHub:

```bash
python3 -c "import secrets; print(secrets.token_urlsafe(48))"
python3 -c "from getpass import getpass; from werkzeug.security import generate_password_hash; print(generate_password_hash(getpass('Пароль: ')))"
```

Вторую команду выполнять в окружении с установленным Flask/Werkzeug.

## Проверка после безопасного развёртывания

1. Открыть `/admin/login` по HTTPS; убедиться, что неверный пароль отклоняется.
2. Войти; открыть `/driver-topup`; список машин должен загружаться.
3. Проверить отклонение запроса без сессии к `/api/driver-wallet/topup`.
4. Проверить отклонение запроса с чужим `Origin`.
5. **Только на тестовой базе** проверить реальное пополнение и корректность двух записей (кошелёк + финучёт). На production не делать фиктивные пополнения.
6. Проверить выход из кабинета и повторный отказ после выхода.
7. Убедиться, что пользовательские кабинеты и платёжные уведомления T-Bank продолжают работать.

## Известные ограничения текущего PR

- Защищены только ручное пополнение, его страница и список автомобилей на странице. Остальные финансовые/административные маршруты пока требуют инвентаризации.
- Вход по паролю пока без rate limiting и CSRF-токена; это обязательные улучшения до публичного развёртывания.
- Требуется резервное копирование базы и план отката.
- Секрет сессии должен быть постоянным между перезапусками и одинаковым на всех экземплярах сервиса.
- Никогда не размещать хэш, пароль, секреты, паспортные данные и ключи в GitHub или чатах.
