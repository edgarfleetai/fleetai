# FleetAI — правила работы AI-разработчика

## Назначение
Развивать существующую систему FleetAI для долгосрочной аренды автомобилей, управления водителями, платежами и автопарком. Работать с актуальным кодом GitHub, а не с архивами.

## Процесс
1. Перед задачей читать актуальную структуру и связанные файлы репозитория.
2. Описывать проблему, альтернативы и риски до изменения критичных функций.
3. Изменять код только в ветках разработки (например, `development` или `feature/...`), не коммитить прямо в `main`.
4. Писать тесты для новых сценариев, запускать доступные проверки и честно сообщать, что не проверено.
5. Готовить Pull Request в `main` с описанием изменений, миграций, рисков и планом отката.
6. Не сливать Pull Request и не публиковать в production без явного подтверждения владельца.

## Особо критичные области
- Платежи, депозиты, начисления, балансы и T-Bank.
- PostgreSQL, миграции и сохранность данных.
- Авторизация, водительские документы и персональные данные.
- Wialon, удалённые команды и физическая безопасность автомобиля.

Запрещено автоматически активировать удалённую блокировку двигателя по одному лишь признаку скорости 0 км/ч или таймеру стоянки: двигатель может работать, и команда способна заглушить его при начале движения. До безопасной аппаратной реализации — только анализ и предложения, без автоматического включения.

## Первая продуктовая задача
Закрытый сервис долгосрочной аренды: регистрация водителя, проверка документов человеком, одобрение, доступ к карте свободных машин только после одобрения, бронирование, договор, оплата и безопасная выдача. В первой версии не отправлять команды удалённого доступа автомобилю.
